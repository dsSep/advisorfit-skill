# 从研究材料到针对导师的邮件：0.2.8开发试用

0.2.8增加了写信前的信息取舍与交付检查：选择一条双方有依据的联系主线，突出本人操作和产物，再检查换导师后是否仍能套用、哪些句子没有判断价值。已有的身份确认、经历真实和明确进组目的继续保留。

这里公开固定输入、改前与改后完整回复及已知限制，方便复查。**这是Codex独立子代理的开发行为试用，不是ChatGPT网页实验、盲评或统计显著性证明。** 人物、学校和研究摘要全部虚构；没有检索网页、调用在线演示模型或发送邮件。

## 实际观察到什么

**无Skill样本出现阅读身份错置。** 输入明确说申请者没有读导师论文，输出却写“从您参与的2025年论文摘要中，我了解到”，并接着写“我目前尚未阅读全文”。它也替申请者提出了新的同名政策文件核验项目。这说明具体导师事实正确，仍可能被写成不真实的本人阅读或未经确认的行动。旧版和新版在这份课程实践样本中都避开了这个问题；不能把已有优点算作0.2.8独有提升。

**新版课程邮件更明确地使用了导师问题。** 新版写出“仅按标题去重可能混淆修订版，需要结合机构、时间及原始来源判断”，连接本人正在进行的40份政策文件来源核对。旧版也已有“保留修订版本”的具体连接，并非只有泛泛标签。新版未再列GPA、排名，保留了课程与数据处理操作；这体现了取舍，但新版仍有重复，不能据此声称普遍更精简。

**已有研究场景，两版都保留了重要边界。** 两版都写本人在老师给定方案下编写对照脚本、固定数据划分、比较两种处理与群体均值、形成一页结果；均未把课程观察写成普遍方法优势。最终新版将本人观察和研究内容分开：“我读过……摘要，注意到有些记录更可能缺失。该研究比较了……”，再解释希望进一步学习缺失假设的影响。初稿第一人称推论归属不够清楚的问题及修改过程保留在独立检查中。旧版也已经解释了相关性，本例不足以证明新版有明显增益。

**信息缺失场景，两版都先问后写。** 补齐后保留“在读硕士”“申请导师指导并加入课题组”，未再索取用户选择省略的成绩、联系方式和年份。最终新版主题为“申请由您担任硕士导师并加入课题组”，把20条目录中的日期规范、来源核对与导师研究集中在一段。旧版“申请担任硕士导师及加入课题组”存在主语歧义，虽其正文目的正确。这个样本呈现了较清楚的取舍，不能代表所有场景都更短或更好。

## 如何执行与核对

- 每个首轮使用新的隔离子代理（`fork_turns=none`），只提供对应输入与所需说明；缺失信息场景的第二轮沿用同一代理，收到同一段固定补充。没有传入开发者前期判断或预期答案。
- 无Skill条件禁止读取Skill；旧版读取已保存的核心及邮件参考；新版读取候选核心及邮件参考。`research`文件保存为变更快照，本轮局部写信试用没有读取它，不能宣称验证了真实研究检索到邮件的全流程。
- 子代理继承当时宿主模型；工具未暴露具体模型标识和推理设置，记录为未知，不以“同一模型已严格控制”宣传。父任务负责材料和知情核对；另有独立缺陷检查，均不是盲评。
- 核对申请者句子是否对应输入，导师研究是否对应固定材料，是否明确申请进组，阅读和计划状态是否正确，是否有占位或不存在的附件；再看针对性、重复和实际信息价值。篇幅不直接计分。

## 尚未验证的部分

这是固定证据下的局部写信检查：不验证自动发现导师、真实网页来源、研究归属、最新招生、账户记忆隔离机制或宿主自动触发；也没有重复运行到足以判断波动。没有测量导师回复、接收或录取结果。新版样本仍有重复措辞，不能宣称所有场景都更好。课程邮件中的“专业B专业硕士”也可能被误读为已确认专硕类型；输入仅确认硕士与专业，学术型／专业型未知。原文保留这一措辞歧义，实际发信应核对后改成不会混淆学位类型的表达。

真实使用时，应由支持检索的ChatGPT／Codex核实导师与论文，确认本人阅读和贡献，再审阅邮件。开发样本不得用于真实联系。
