# 当前产品边界与验收路线

## 想交付的完整流程

用户上传或粘贴简历 → 确认目标学校及关键背景 → 选择找候选/分析一位/比较多位 → 读取真实来源并解释研究匹配 → 用户确定导师 → 入门准备与完整针对性进组邮件 → 用户审阅自行发送。项目实践可选，不是写邮件的前提。

## 现在分别在哪一步

| 部分 | 当前交付 | 仍未证明/未提供 |
|---|---|---|
| 完整Skill 0.2.5 | 已提供完整工作说明，覆盖三场景、按需研究/准备/邮件、经历边界和后续辅导 | 需要宿主能读取简历及联网搜索；说明存在不证明每次稳定执行。未完成三场景真实网页全链路重复验收 |

| 邮件 | Skill及指定导师演示能交邮件草稿，已确认真实生成 | 生成仍可能有未经确认的自我评价；需事实审核。对真实研究的准确性依赖检索证据 |
| MCP与旧工程 | 保留原服务和代码，公开Skill包不内置已连接MCP | 本站未调用MCP，不自动升级账户插件或旧服务，不把旧工程存在算成新版全链路已落地 |

Skill不是独立应用程序：在支持文件与搜索的助手里，用户可上传简历后按流程用它；这不代表Sites网页已有上传入口。GitHub发布不自动升级账户内插件；复测前核对实际加载版本。

## 现在怎样测

先按[空白账号协议](../evals/manual-blank-account/README.md)，用全虚构简历测指定导师到邮件和最小第一步。再分别测找候选、比较，统一确认导师后走到邮件。记录真实资料与虚构申请者的边界，不做真实联系。

后续产品开发分三步：先让用户上传/粘贴简历并确认事实；再让三个入口共用真实检索、来源及选定导师状态；最后把选择、准备和可审阅邮件接成连续流程。每步验证用户能完成的动作，不能用新的页面或检查数量替代成果。此处是路线说明，本次未擅自新增上传/联网或改变个人数据存储。
