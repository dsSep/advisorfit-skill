## B站60–120秒视频

标题备选：**AI套磁最怕把“计划”写成“成果”：我做了一个可复用的工作说明**；**不用每次写一屏提示，让AI按步骤帮你选导师**。

- 0–15秒：虚构学生说想进组，但没做建议项目；展示邮件必须保持真实。
- 15–35秒：三个入口：没有目标、指定一位、比较多位；镜头聚焦用户输入与交付。
- 35–60秒：同材料修改简短问题并实时运行 AdvisorFit，说明实际加载核心与参考，结果会波动，不预设胜负。
- 60–85秒：演示“只比较”和“带做第一步”，再看邮件里的真实经历与未知。
- 85–105秒：完整技能目录、安装与ZIP校验；说明DeepSeek V4.1 Flash、虚构材料、无实时搜索、登录后限额。
- 105–120秒：新版优势尚未证实，邀请读源码和限制、自行复现，邮件自己审阅发送。

60秒版压缩中间演示，保留一个经历边界例子。发布含 AI 生成内容时参考 [B站官方公告](https://www.bilibili.com/opus/1202507670848798745)。不要将旧分数、九次运行报告或待跑18次评测剪成“0.2.4已证实更强”。

统一入口：[完整对照案例](cases/case-002/README.md)。先显示真实摘录，再让读者点开完整回答和限制，不只截获胜片段。

标题备选：

- “从100—200份政策文件到复用现有40份：一次导师分析试用记录”

建议60–90秒素材顺序：5秒简短请求和虚构背景 → 20秒项目范围/时间的双栏原句 → 15秒经历连接 → 15秒公开共同缺陷 → 15秒说明新版本改变哪三个动作 → 入口与复现邀请。画面标出“0.2.4单次探索，非录取建议”。不混用在线API演示的模型与本次网页记录，不隐去普通组的思考设置更正（两组均未开启）。

避免使用“已显著提升”“普通AI完全做不到”“0.2.5已经胜出”以及提高录取率等未证实表述。作者披露开发者身份，按发布平台界面标识AI内容；本任务不自动发帖。
