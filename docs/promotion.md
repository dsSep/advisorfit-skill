# GitHub、知乎、B站推广草稿

供作者审核后自行发布，没有自动发帖或上传。统一定位：减少重复长提示，让找导师、匹配和真实邮件更有条理。普通助手配合完整提示也可表现很好；不宣传已证实的优越性、录取保证或平台认证。

## GitHub

标题：**AdvisorFit 0.2.4：让助手更有条理地找导师、比较研究、准备进组邮件**

正文：提供完整Skill目录与插件ZIP；研究、准备、邮件按需读取，保留来源、未知与真实经历边界。用固定虚构案例体验Sites演示。新版补齐完整打包、源文件哈希和同步检查，修正时间窗口和主线数量。历史证据与局限公开；没有已连接MCP，不自动发送邮件。发布时附README、源码、MIT许可、最终ZIP与校验值；仓库和演示地址待真实发布后填写，不使用占位链接。

## 知乎

标题：**用AI找导师，怎样少写长提示，又不把“建议做的项目”写成“已经做过”？**

顺序：展示虚构学生输入 → 说明普通助手也能完成 → 解释反复写长提示的负担 → 演示已完成/计划/未知的区分 → 比较后再写真实邮件、按30分钟带做第一步 → 安装方法与局限。明确材料虚构且不联网，旧分数不证明0.2.4优势；邀请相同材料、完整提示下自行复现。

## B站60–120秒视频

标题备选：**AI套磁最怕把“计划”写成“成果”：我做了一个可复用的工作说明**；**不用每次写一屏提示，让AI按步骤帮你选导师**。

- 0–15秒：虚构学生说想进组，但没做建议项目；展示邮件必须保持真实。
- 15–35秒：三个入口：没有目标、指定一位、比较多位；镜头聚焦用户输入与交付。
- 35–60秒：同材料修改简短问题并实时运行 AdvisorFit，说明实际加载核心与参考，结果会波动，不预设胜负。
- 60–85秒：演示“只比较”和“带做第一步”，再看邮件里的真实经历与未知。
- 85–105秒：完整技能目录、安装与ZIP校验；说明DeepSeek V4.1 Flash、虚构材料、无实时搜索、登录后限额。
- 105–120秒：新版优势尚未证实，邀请读源码和限制、自行复现，邮件自己审阅发送。

60秒版压缩中间演示，保留一个经历边界例子。发布含 AI 生成内容时参考 [B站官方公告](https://www.bilibili.com/opus/1202507670848798745)。不要将旧分数、九次运行报告或待跑18次评测剪成“0.2.4已证实更强”。
