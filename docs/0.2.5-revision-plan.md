# 0.2.5修订方案：从原则提醒变为交付动作

状态：方案，尚未修改Skill或发布0.2.5。依据是一次0.2.4真实短提示输出；用户已更正两组均未开启思考模式。保留观察到的改善与缺陷，不宣称因果或统计显著性。

## 1. 不替用户否认未知经历

实际问题：同一份增强组报告既写“没有复杂模型训练经历（待提升）”，又写“复杂模型开发：未知/待培养”。前一句会让用户误把未经确认的能力当短板，甚至带进邮件。

针对修改：把“用户事实”检查移到匹配写作前。对本轮要使用的每项经历，先对应简历原句，区分已完成/进行中/计划/未知/明确否认；只有明确否认或明确限制才支持“没有、不会、缺乏”。交付前检查段落、表格及邮件是否使用同一状态。无需向用户展示全部内部记录，也不为无关未知项反复追问。

合格例子：“复杂模型训练经历未提供，暂不能据此判断能否承担模型训练。”明确没有训练过之后，才可改成“目前尚无训练实践”。新增的是状态核对发生的时机、否认所需依据和跨段一致性检查；旧版已有“未知不等于不会”，不冒称新原则。

## 2. 让论文真正能读、能理解

实际问题：一篇核心论文给的是CNKI首页，后文虽承认不是条目入口，用户仍无法直接找到它。部分介绍主要是“你可以思考什么”，没有说清论文实际方法和发现。列更多论文不等于研究分析更好。

针对修改：每篇拟作为匹配依据的核心论文先检查作者/年份/具体条目、实际阅读层次，以及原文支持的问题、方法和发现；有摘要则按摘要范围解释，有全文才补全文细节。只有题录的放“待核实线索”，不能以自拟阅读问题代替论文发现。首页只能标“数据库检索入口”；找不到条目时原位写清缺口，不用结尾统一免责声明冲掉前面的错误标签。内容重复时减少清单，不用凑数量。

验收：用户可点击到明确论文条目，或立即看到尚未取得的说明；每个方法/发现能追溯实际读到的来源。“论文讲了什么”与“你读它能想什么”分开。本例同名项目也确有论文，不将它误记为虚构论文。

## 3. 让小项目当天就能开始

实际问题：增强组已比普通组更节制，复用40份材料并算出10.5小时，但第一步仍是整批检查。它没有清楚说明用户现在交什么、助手做什么、怎样知道做对了。

针对修改：预览先区分“最小版本”和“后续扩展”。已有40份文件是可复用材料池，首步只取1–3条，不把40当作起步门槛。每个首步交付四件事：最少输入、助手协助、一个可见产物、核对标准；材料已给就当场示范一条，没给就只索取最小必要输入，不假装已读。

本例起步示范：“请贴1份政策文件的官方链接，或标题、机构、日期及对应原文。我帮你整理成一行记录，并给每格标原文依据；你核对机构是否确实是发布机构、日期是否是文件发布日期。”10–20分钟内先得到1行可检查记录，再逐步扩到40份。项目不是联系导师前置条件，未做的部分不写进邮件成果。

## 发布前如何判断有无修好

先保留0.2.4实际失败原文，再改核心说明中相关步骤及按需参考，新增一个正反例，避免把同一规则复制到许多地方。按[定向复验](../evals/manual-blank-account/regression-followups.md)检查上述三个动作，再换一份背景或其他研究方向确认能迁移，最后检查完整邮件。普通组、旧版和新版本各自留档，不覆盖原始输出；失败也记录。

打包检查负责版本、资源与文件同步；行为复验负责事实状态、论文可读性和第一步。二者分开。只有实际完成后才写0.2.5修复记录并发布；不预先宣传稳定改进，不自动更新账户插件或旧MCP服务。
