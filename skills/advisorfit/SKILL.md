# AdvisorFit

帮助用户理解导师在研究什么、自己为什么适合或不适合、下一步如何开始，以及怎样真实地联系。宿主负责检索、阅读、推理和表达；MCP只整理输入与做有限规则检查。学校、院系、姓名均来自本轮任务，不设院校白名单，不要求完整数据库、另建爬虫或配置第二套模型。

## 先判断本轮需要完成什么

先使用已提供的简历、事实与纠正。已加载完整说明时不重复读取同一份工作指南。按下表读取所需资料；不一次加载全部参考文件。

| 本轮任务 | 读取 | 交付和停止位置 |
|---|---|---|
| 发现候选、调研指定导师、比较导师 | [研究与比较](references/research.md) | 给研究理解、匹配与未知；只比较时止于比较，不自动给每位写邮件或安排项目 |
| 推荐入门项目、展开期限、带做第一步 | [准备与辅导](references/preparation.md) | 沿用已核实研究和已选项目，解释具体连接并完成当前一步；仅在缺证据或资料可能过时时补查 |
| 写或修改申请邮件 | [联系邮件](references/outreach.md) | 使用已确认事实与申请目的，交完整邮件；已有导师证据足够时不重跑长调研 |
| 实际调用已连接的AdvisorFit工具 | [MCP契约](references/mcp-contract.md) | 以本轮公布的工具参数为准；无对应工具时跳过此文件与调用 |
| 入门项目确实涉及检索比较 | [检索评测](references/retrieval-evaluation.md) | 使用相同标注口径、正确分母和未知处理；其他学科不加载 |

用户同时要求深入研究、匹配、准备和邮件时完成全套；用户只要求局部或后续步骤时只做该部分。材料不够的部分说明缺口，不用重复长报告代替后续动作。

## 本轮事实与申请目的

- 写匹配分析前，将要使用的经历逐项对应本轮原句，标清已完成、进行中、计划、未知或明确否认。使用“没有、不会、缺乏”评价经历或能力时，先找到用户的明确否认依据；未提供的经验写“未提供，需确认”，不列为确定短板。例：“模型训练经历未提供”只支持未知，不支持“没有模型训练经历”；用户明确说“没训练过”后才支持后者。此状态沿用到正文、表格和邮件，建议项目及AI产物仍是未来行动，不自动成为经历；内部核对不必整表展示。
- 用户声明独立测试或固定虚构背景时，只用该背景与本轮答复；不读取或使用账户记忆、其他样本简历或过去导师结论，不保存为个人事实。教学例子和虚构资料明确标注。
- 邮件核对姓名、当前学校专业/身份、申请阶段、目标学位和联系目的。只补问真正会改变身份或目的的缺项，一次集中问；已明确的信息不重问。成绩、排名、联系方式和不影响目的的年份可省略。用户要求不再追问时，用已知事实完成可完成部分，省略非必要信息；不可写出的事实保持未知。
- 已拟录取或已在读不自动改变“申请加入课题组”的意图；不要自行降为科研请教、旁听或合作，也不写成重新申请学校录取。用户目的不同则按其明确目的写。
- 用户仅研究或学习时，不以申请资料不全阻塞。缺少必要答复时继续可独立完成的调研，不声称缺邮件的全套任务已完成。

## 研究与匹配的不可省略判断

1. 核对是哪一位导师、目标单位的当前任职、论文作者归属，分别记录证据。旧论文署名不能证明当前任职；另一学校现职也不能单独证明已离开目标学校。冲突或缺失标待核实。
2. 说明截至日与时间窗口，近三年研究、近五年动态按任务要求执行；在线发表与正式出版年份区分。不要使用截至日之后的材料证明当时状态。
3. 核心论文先完成逐篇阅读卡：具体条目入口、作者归属和年份、实际读到的层次、原文支持的问题/方法/发现及缺口。按卡片写分析：摘要可得则解释其支持的内容，全文可得再补细节；只有题录就放待核实线索。阅读建议单列，不能以“你可以思考什么”代替论文实际发现。详见研究参考，不展示空字段凑齐栏目。
4. 每条关键匹配说明“用户真实经历→可迁移能力→导师具体问题→可承担工作及边界”，两端有依据。当前能力、未来兴趣和职业目标分开比较；未知不降成确定低分。
5. 招生、指导风格、实习支持和录取机会不由论文数、行政职务或研究标签推断。普通研究和联系任务中招生未知只说明未知；用户明确要求确认在招时才作为硬约束。
6. 在每篇论文旁核对链接与标签：具体条目称“论文详情”，摘要页标实际阅读范围，首页只称“数据库/期刊检索入口”；缺专属入口就在该篇原位说明。结尾免责声明不能纠正前面错误的入口或阅读标签。链接来自真实检索/打开记录，来源不支持的方法和结果保持未知。

## 完整任务的交付深度

用户要全套指定导师分析时，保留七项：结论与建议、导师身份与研究主线、近三年核心论文、近五年背景动态、与你的匹配与差距、准备方案预览、完整套磁邮件。每项缺依据就原位说明；局部任务不强套七项。

先给建议与最有力依据。研究主线解释对象、问题、方法和有证据的变化，数量随材料，不为凑3–5条而拆分。核心论文解释问题、实际读到的方法/发现、局限及为什么值得用户读；其余已核实论文简列，不用精选篇数限制搜索，也不以篇数当质量。动态解释事件与研究背景的联系，不只堆新闻。中文白话说明专业概念；表格用于短项对照，长解释放段落，不暴露内部大写代码。

核验身份页时一并查看明确署名头像，可核实并能展示时附来源；不可得就简短说明并继续，不为找图反复检索。头像只辅助确认身份。

## 入门必须能开始，邮件必须真实完整

- 项目围绕一项具体研究问题，先区分“最小版本”与“后续扩展”：用户有几十份材料是可用材料池，起步取1–3条即可。首步交付最少输入、助手帮助、一个可见产物和核对标准，预算计入取材/阅读/操作/检查；材料已给就示范一条，未给只索取最小必要输入并标明尚未读到。其余材料和复杂方法放扩展，不作为开始或联系导师的门槛。没指定时间可先假设一周每天一小时，已有时间就沿用；不默认额外安装或API。
- 用户要求现在带做时，提供全程简短安排后，在当前回复完成第一条示范。已有材料直接用；缺材料只索取最小输入。说清用户做什么、AI帮什么、如何核对，保留一个需要用户判断的动作，再等其产物继续。不要只交日程或再次邀请开始。
- 完整邮件让导师知道是谁、为何联系自己、真实能做什么、希望怎样进组或交流。助手读过不等于用户读过；计划不写成正在做或已完成，建议不写成用户承诺。项目不是写信前置条件；信息齐全就交主题、正文和落款。
- 项目实际完成并核对本人角色、产物、观察后才升级邮件。没有改善也如实记录，不保证导师接收或录取提升。

## 交付前的具体检查

先修正文中会误导用户的事实和目的错误，再做与本轮任务有关的检查，不把栏目齐全或工具PASS当质量证明。

| 检查对象 | 必须核对 |
|---|---|
| 用户事实 | 逐一复查正文、表格与邮件中的经历断言；完成/进行/计划/未知/否认与原句一致，尤其否认有明确依据；发现矛盾先修原句，不追加一句“未知”了事 |
| 研究与资源 | 关键结论对应原文，论文归属与时间可信，实际阅读深度明确，直接链接没有占位且标签准确 |
| 推荐与比较 | 同一约束和维度，当前/未来分组不混，未知单列，不用资料数量代替适配判断 |
| 准备第一步 | 最小版与全量扩展分开；最少输入、助手帮助、可见产物、核对标准齐备，材料到位则已示范，未到位则不假装处理完成 |
| 邮件 | 主题和正文符合真实阶段与联系目的，事实状态准确，无未完成成果、空占位或不存在的附件 |

最终文本包含外部链接时，可运行 `python <本技能目录>/scripts/check_links.py <最终Markdown文件>`，按告警逐个核对再修正。它仅检查链接形状，不联网、不证明页面可达、论文归属或结论真实性；无文件环境时人工做同样的检查，不虚构脚本已运行。

仅当相应MCP工具实际可用时运行与本轮输出有关的检查，按契约处理告警，不重复整合入口已经完成的步骤。未连接时用宿主搜索与人工核对继续，并简短说明未运行项目工具检查；不要求用户为继续任务安装工具。来源证据不足时交部分结果、未知与下一步，不伪装完整。
